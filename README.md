## Весь SQL на сегодня

Предполагаем, что SQL ты видишь впервые. Для всех обязательных заданий хватит 6-ти конструкций и одного приёма - подробно и с примерами в `materials/sql_start_rus.md`:

| **Конструкция** | **Что делает** | **Пример** |
| --- | --- | --- |
| `SELECT … FROM …` | взять поля из таблицы | `SELECT topic, priority FROM clean LIMIT 5` |
| `WHERE` | оставить только подходящие строки | `WHERE period = 'после' AND written = 1` |
| `ORDER BY` | отсортировать | `ORDER BY 2 DESC` |
| `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`, `ROUND` | посчитать | `COUNT(*)`, `COUNT(DISTINCT client_id)`, `ROUND(AVG(handle_min), 1)` |
| `GROUP BY` | посчитать отдельно по каждой группе | `GROUP BY topic` |
| `HAVING` | оставить только нужные группы | `HAVING COUNT(*) > 100` |

Кто знает SQL лучше - для тех бонусное Задание 8.

## Задание 2. Сколько людей и сколько времени

Руководитель второй линии первым делом спросит две вещи: сколько у вас людей и сколько времени они тратят на одно обращение. На оба вопроса легко ответить неправильно — и после этого тебя уже не будут слушать.

Ещё в SQLite не хватает двух инструментов, без которых дальше не обойтись: медианы и нижнего регистра для русских букв. Их ты напишешь самостоятельно.

Работаешь в `src/ex02.py`. База подключается строкой `con = connect()`, в ней уже есть справочник `agents`, сырая выгрузка `tickets` и очищенная таблица `clean`.

**Что сделать:**

1. **Сколько людей на первой линии.** Сравни число строк в справочнике и число разных сотрудников (`COUNT(*)` и `COUNT(DISTINCT login)`). Если они разные — найди запросом строку, из-за которой так вышло. На сколько можно ошибиться, если назвать штат по числу строк?
2. **Из каких смен некого забрать.** Вторую линию будут собирать из людей первой. Покажи смены, где меньше шести человек: там уход даже одного уже заметен. Считай людей, а не строки. Понадобятся `GROUP BY` и `HAVING`.
3. **Сколько обращений пришло через чат.** Сгруппируй сырую выгрузку `tickets` по каналу, приведённому к нижнему регистру встроенной функцией `lower()`, и посмотри на результат. Потом напиши свою функцию `unicode_lower`, зарегистрируй её в базе и сгруппируй ещё раз. Сколько обращений в чате на самом деле? Если в поле `NULL`, в функцию придёт `None` — она должна вернуть `None` и не упасть.
4. **Сколько времени люди тратят на обращение.** Напиши класс `Median` — свою агрегатную функцию `MEDIAN`. Посчитай по таблице `clean` за время до 1 апреля (`period = 'до'`, тогда работали только люди) среднее и медиану времени обработки `handle_min`. Почему они так расходятся? Какое число ты назовёшь руководителю? Ответь одной строкой в комментарии в коде.
5. **Проверь свой инструмент.** Прежде чем нести числа руководителю, убедись, что `MEDIAN` считает правильно. Достань те же значения запросом, посчитай медиану на Python (`statistics.median`) и напечатай оба числа в одной строке. Они должны совпасть.

Встроенную `median()` не используй, даже если она есть в твоей версии SQLite. В стандартной сборке SQLite `lower()` меняет только латиницу. В некоторых сборках (с расширением ICU) он работает и с кириллицей — проверь у себя. Своя функция нужна, чтобы запрос давал один и тот же результат на любой машине.

Как устроена своя агрегатная функция — в `materials/sql_start_rus.md`, раздел «Свои функции». В шаблоне уже есть заготовка класса: осталось дописать 2 метода.
