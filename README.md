## Как устроена программа

Программа состоит из двух файлов:

- `src/main.py` — **уже готов.** Он принимает путь к банку и флаг, вызывает функции из `bank.py` и печатает результат.

> *Что такое «Флаг».*
>
> *Флаг — это слово с двумя дефисами, которое пишут в команде после пути к банку, например `--stats`. Он говорит программе, что сделать с банком. Все флаги есть в списке ниже. Если флага нет, программа просто считает вопросы.*

- `src/bank.py` — **твой.** В нём 6 функций, которые читают банк и считают: 5 для основных заданий и `count_matrix` для дополнительного Задания 8. Их названия и описания уже написаны, а тела — нет: пока функции возвращают пустые значения, и программа отвечает нулями. Сами функции ничего не печатают — они возвращают результат, а печатает `main.py`.

Запуск:

```
python3 src/main.py ПУТЬ_К_БАНКУ              # сколько вопросов (Задания 1 и 4)
python3 src/main.py ПУТЬ_К_БАНКУ --show ID    # показать вопрос (Задание 2)
python3 src/main.py ПУТЬ_К_БАНКУ --stats      # сколько вопросов каких (Задание 3)
python3 src/main.py ПУТЬ_К_БАНКУ --matrix     # таблица тем и уровней (Задание 8)
```

`ПУТЬ_К_БАНКУ` — путь к файлу, например `datasets/bank.csv`. `ID` — номер вопроса, например `23`.

После каждого задания проверяй себя двумя командами. Что они делают и как читать их ответ — в `materials/tests_and_linter_rus.md`.

```
python3 testing/test_bank.py НОМЕР_ЗАДАНИЯ
python3 src/partner/lint.py src
```

Используй сегодня Python без сторонних библиотек.

## Задание 2. Покажи вопрос

Флаг `--show ID` показывает один вопрос так, как его увидит человек на экзамене. Печатает `src/main.py` — он уже готов.\
Твоя часть — две функции в `src/bank.py`. Что каждая из них получает и что возвращает, найди там же.

**Шаг 1. Найди вопрос**

`find_question` перебирает список вопросов и возвращает тот, у которого нужный номер.

**Подсказка:** для Python `"23"` (строка) и `23` (число) — разные вещи, и сравнение между ними всегда даёт `False`. Проверь, в каком виде номер приходит в функцию и в каком лежит в вопросе.

**Шаг 2. Собери строки для экрана**

`question_lines` возвращает список строк. `main.py` печатает каждую строку списка с новой строки.\
В список входят:
-	текст вопроса. Если в тексте есть перенос строки, на экране он должен стать настоящим переносом. Как перенос записан в файле банка — в `materials/bank_format_rus.md`;
-	варианты ответа, если они есть у вопроса. Каждый — с номером, скобкой и пробелом: `1) print`. Где в банке лежат варианты и чем они разделены — тоже в `materials/bank_format_rus.md`.
Пустых строк в выводе нет. Удобно идти по частям: сначала добейся, чтобы печатался только текст вопроса, потом добавь варианты.

Как должно получиться

`python3 src/main.py datasets/bank.csv --show 1` печатает:
```

1) print
2) input
3) int
4) len
```
`python3 src/main.py datasets/bank.csv --show 23` печатает (у этого вопроса вариантов нет):
```
Что напечатает код?
items = [3, 1, 2]
print(items[0])
```
Сохрани коммитом и сделай пуш `develop` в GitLab.
**Результат:** в `src/bank.py` написаны `find_question` и `question_lines`.

Проверяющий открывает `datasets/bank.csv`, выбирает ещё два вопроса — один с вариантами, один без — и сверяет вывод `--show` с банком.

## Задание 6. От затруднения к проверяемому действию

Поэтому по опыту проведенного дня преврати затруднение в конкретную задачу и найди проверяемый следующий шаг — этот приём поддерживает стрессоустойчивость и помогает продолжать работу при сложностях.

3. **Наблюдаемый факт.** Что именно не получилось или осталось непонятным? Укажи конкретный результат, ошибку или расхождение с ожиданием.
Первоначальное объяснение. Какое объяснение этого затруднения было у тебя сначала? Достаточно одной фразы.

4. **Конкретный пробел.** Что именно нужно уточнить или проверить в понимании задачи, логике решения или способе работы? Если причина пока неизвестна, сформулируй гипотезу.

5. **Действие и проверка.** Что уже удалось попробовать или что планируешь сделать следующим шагом? Как проверишь результат и что должно произойти, если действие поможет?

Ожидаемый результат — 40 загруженных вопросов».

Если рассуждения сразу были конкретные, не нужно придумывать негативную реакцию или менять верное объяснение. Покажи исходную гипотезу и способ её проверки. Можно выбрать небольшой вопрос, который потребовал уточнения, даже если серьёзных затруднений не было. Для выполнения задания достаточно определить проверяемый шаг.
