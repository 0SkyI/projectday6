# SQL с нуля

SQL - язык запросов к таблицам. Таблица - набор строк одного вида с одинаковыми полями: одна строка - одно обращение в поддержку или один сотрудник.

Главное отличие от Python: в запросе описываешь, **что** хочешь получить, а не **как** это обойти. Ты не пишешь цикл по строкам - ты говоришь “сгруппируй по каналу и посчитай количество”, а база сама решает, как читать данные. То, что на Python занимает 30 строк со словарями, в SQL занимает 3.

Сегодня тебе хватит **шести конструкций и одного приёма**. Всё, что ниже раздела "Для бонуса", для обязательных заданий не нужно.

## Как запускать запросы: пошагово

### Что вообще происходит

Мы работаем с **SQLite** - это база данных, которая умеет жить без отдельного сервера. Модуль `sqlite3` для работы с ней уже входит в Python - ставить ничего не нужно.

Каждый раз, когда ты запускаешь любой скрипт проекта, происходит одно и то же:

1. Скрипт `src/db.py` создаёт пустую базу в памяти.
2. Загружает в неё оба файла из `data/`: получаются таблицы `agents` и `tickets`.
3. Строит из них таблицу `clean` (очищенные обращения) и таблицу `razmetka` (обращения плюс твоя разметка из `src/razmetka.csv`).
4. Выполняет твои запросы и печатает результат.
5. Когда скрипт заканчивает работу, база исчезает.

Отсюда два следствия. Сломать данные запросом нельзя: при следующем запуске всё соберётся заново из файлов. И любое изменение в твоих файлах - например, в `razmetka.csv` - видно сразу при следующем запуске.

### Шаг 4а. Запросы в .py-файле - задания 1 и 2

Файл открываешь в любом текстовом редакторе: VS Code, gedit, nano - что установлено на твоём компьютере. Вот минимальный скрипт, разберём его построчно:

```python
from db import connect

con = connect()

for row in con.execute("SELECT login, team FROM agents LIMIT 3"):
    print(row)

print(con.execute("SELECT COUNT(*) FROM agents").fetchone())
```

| **Строка** | **Что она делает** |
| --- | --- |
| `from db import connect` | Берёт функцию `connect` из файла `src/db.py`. Скрипт лежит в той же папке `src/`, поэтому Python этот файл находит. |
| `con = connect()` | Собирает базу со всеми таблицами (шаги 1–3 из "Что вообще происходит"). В переменной `con` - **соединение** с базой: через него отправляются все запросы. |
| `for row in con.execute("SELECT …"):` | `con.execute(…)` отправляет в базу текст запроса и возвращает результат - строку за строкой. Цикл `for` перебирает эти строки. |
| `print(row)` | Печатает очередную строку результата. |
| `print(con.execute("SELECT COUNT(*) …").fetchone())` | `fetchone()` забирает из результата одну, первую строку. Удобно, когда ответ - одно число. |

Чтобы попробовать, сохрани эти пять строк в файл `src/proba.py` и запусти его из корня:

Сейчас файла нет, нужно создать `nano src/proba.py`

```bash
$ python3 src/proba.py
```

```text

('anna_k', 'дневная смена')
('pavel_m', 'дневная смена')
(20,)
```

`src/proba.py` - файл для проб: коммитить его не нужно.

Каждая строка результата приходит **кортежем** - поэтому в выводе скобки.

**Кортеж** - это несколько значений в круглых скобках через запятую. Он похож на список, только его нельзя изменить. В кортеже лежат значения полей строки - в том порядке, в каком ты перечислил поля после `SELECT`:

- `SELECT login, team …` → `('ivan_p', 'дневная смена')`: первое значение - логин, второе - смена;
- `SELECT COUNT(*) …` → `(20,)`: кортеж из одного значения. Запятая перед скобкой - не опечатка: так Python отличает кортеж из одного значения от обычного числа в скобках.

Достать отдельное значение можно по номеру, начиная с нуля: `row[0]` - первое, `row[1]` - второе. Если нужно само число без скобок: `con.execute("SELECT COUNT(*) FROM agents").fetchone()[0]` вернёт 20.

В заданиях 1 и 2 печатай результат как есть, кортежами - так сравнивать вывод с ожидаемым проще всего.

Как записывать запрос внутри Python:

- Текст запроса - строка Python в двойных кавычках: `"SELECT …"`. Текстовые значения внутри запроса - в одинарных: `"SELECT login FROM agents WHERE team = 'ночная смена'"`.

- Длинный запрос удобно писать на нескольких строках, в тройных кавычках:

```python
query = """
SELECT team, COUNT(*)
FROM agents
GROUP BY team
"""

for row in con.execute(query):
    print(row)
```

В `ex01.py` база собирается не через `connect()`, а вручную - прямо в начале файла. Так видно, как CSV-файл превращается в таблицу. Начиная с `ex02.py` - через `connect()`.

## Шесть конструкций

### 1. SELECT … FROM … - взять поля из таблицы

```sql
SELECT login, hired_at FROM agents; -- два поля, все строки
SELECT * FROM clean LIMIT 5;        -- все поля, первые 5 строк
```

`LIMIT n` - показать только первые n строк. Удобно, чтобы посмотреть, что лежит в таблице.

### 2. WHERE - оставить только подходящие строки

```sql
SELECT login FROM agents WHERE team = 'ночная смена';
SELECT COUNT(*) FROM clean WHERE period = 'после' AND written = 1;
SELECT COUNT(*) FROM clean WHERE channel IN ('чат', 'почта');
SELECT COUNT(*) FROM clean WHERE agent_id IS NULL;
SELECT COUNT(*) FROM tickets WHERE created_at LIKE '__.__.____%';
```

- Сравнения: `=`, `!=`, `<`, `>`, `<=`, `>=`. Текст - в одинарных кавычках: `'после'`.
- `AND` - оба условия, `OR` - хотя бы одно.
- `IN ('а', 'б')` - значение из списка.
- `IS NULL` - значения нет (про `NULL` - ниже).
- `LIKE` - похоже на шаблон: `_` - ровно один любой символ, `%` - сколько угодно символов. `'__.__.____%'` - "две цифры, точка, две цифры, точка, четыре цифры, дальше что угодно".

### 3. ORDER BY - отсортировать

```sql
SELECT login, hired_at FROM agents ORDER BY hired_at; -- по возрастанию
SELECT login, hired_at FROM agents ORDER BY hired_at DESC; -- по убыванию
SELECT topic, COUNT(*) FROM clean GROUP BY topic ORDER BY 2 DESC; -- по второму полю результата
```

### 4. COUNT, SUM, AVG, MIN, MAX, ROUND - посчитать

```sql
SELECT COUNT(*) FROM clean; -- сколько строк
SELECT COUNT(DISTINCT client_id) FROM clean; -- сколько разных значений
SELECT SUM(came_back) FROM clean; -- сумма
SELECT ROUND(AVG(handle_min), 1) FROM clean; -- среднее, округлённое до 1 знака
SELECT MIN(created), MAX(created) FROM clean; -- самое раннее и самое позднее
SELECT MEDIAN(handle_min) FROM clean; -- медиана - твоя функция из задания 2
```

Арифметику можно делать прямо в запросе: `SELECT MAX(num) - COUNT(*) FROM clean`.

`AVG`, `SUM`, `MIN`, `MAX` и `MEDIAN` пропускают `NULL`: у обращений, которые закрыл бот, `handle_min` пустой, и в среднее они не попадут.

### 5. GROUP BY - посчитать отдельно по каждой группе

```sql
SELECT team, COUNT(*) FROM agents GROUP BY team;
SELECT period, written, ROUND(AVG(first_reply_min), 1) FROM clean GROUP BY period, written;
```

Всё, что стоит в `SELECT` рядом с `COUNT`/`AVG`, должно стоять и в `GROUP BY`.

### 6. HAVING - оставить только нужные группы

```sql
SELECT team, COUNT(*) FROM agents
WHERE hired_at < '2024-01-01' -- WHERE: отбор строк ДО группировки
GROUP BY team
HAVING COUNT(*) >= 3; -- HAVING: отбор групп ПОСЛЕ подсчёта
```

`WHERE` не может использовать `COUNT(*)`: в момент, когда он работает, групп ещё нет.

## Приём: доля - это AVG от условия

В SQLite условие даёт 1 (да) или 0 (нет). Среднее из единиц и нулей - это доля единиц. Умножь на 100 - получишь процент:

```sql
SELECT ROUND(AVG(team = 'ночная смена') * 100, 1) FROM agents; -- 25.0: каждая четвёртая строка - ночная смена

SELECT blok, ROUND(AVG(bot_result = 'закрыл') * 100, 1) -- доля закрытых ботом
FROM razmetka WHERE period = 'после' AND written = 1 GROUP BY blok;

SELECT ROUND(AVG(reopened = 0 AND came_back = 0) * 100, 1) FROM clean; -- доля обращений без переоткрытия и без возврата
```

Почти все запросы заданий 4–5 устроены по одному шаблону:

```sql
SELECT <по чему делим>, ROUND(AVG(<условие>) * 100, 1)
FROM razmetka
WHERE <кого сравниваем>
GROUP BY <по чему делим>;
```

## Пустая строка, NULL и текст "NULL"

**Пустая строка не равна отсутствию значения.** `NULL` означает "значения нет". Пустая строка `''` - это значение, просто пустое. Условия `поле IS NULL` и `поле = ''` ловят разные строки. В `tickets` пустые ячейки лежат пустыми строками, в `clean` коллега часть из них превратил в `NULL`.

**Сравнение с NULL не возвращает ни "да", ни "нет".** Оно возвращает "неизвестно", и строка не проходит фильтр - ни при `= 'значение'`, ни при `!= 'значение'`. Ошибки нет, строк меньше, никто не замечает.

**Текст `'NULL'`** - это четыре буквы, а не отсутствие значения. SQL его никак не отличает от любого другого слова.

## Свои функции

Встроенных функций SQLite не всегда хватает. Недостающие можно написать на Python и зарегистрировать в базе.

**Обычная функция** получает одно значение и возвращает одно значение - вызывается для каждой строки:

```python
def double(x):
    if x is None:  # в поле NULL - в Python придёт None
        return None
    return x * 2

con.create_function("double", 1, double)  # имя в SQL, число аргументов, функция
con.execute("SELECT double(21)").fetchone()  # (42,)
```

**Агрегатная функция** получает много значений (все строки группы) и возвращает одно - как `COUNT` или `AVG`. Её пишут классом из двух методов: `step` вызывается для каждой строки группы, `finalize` - один раз в конце. Класс - просто "коробка", где между вызовами хранятся накопленные значения. Пример - функция, которая считает, сколько в группе непустых значений:

```python
class CountFilled:
    def __init__(self):
        self.n = 0  # то, что копим между вызовами

    def step(self, value):  # SQLite вызывает для каждой строки
        if value not in (None, ""):
            self.n += 1

    def finalize(self):  # SQLite вызывает один раз в конце
        return self.n

con.create_aggregate("count_filled", 1, CountFilled)
con.execute("SELECT team, count_filled(hired_at) FROM agents GROUP BY team").fetchall()
```

`MEDIAN` из Задания 2 устроена так же: `step` собирает значения в список, `finalize` возвращает медиану.

## Для бонуса

Этого нет в обязательных заданиях. Для Задания 8 понадобятся инструменты SQLite, которых нет в основном наборе. Как именно их применить - разберись сам: документация SQLite, поиск и ИИ сегодня доступны.

- `CASE WHEN … THEN … ELSE … END` — условие внутри запроса, как `if`;
- `substr(текст, с какого символа, сколько символов)` и `||` — вырезать кусок текста и склеить строки;
- `CAST(… AS INTEGER)` — превратить текст в число;
- `NULLIF(a, b)` — получить `NULL`, если `a` равно `b`;
- `julianday(дата)` — превратить дату в число дней, чтобы считать интервалы;
- `JOIN … ON` — соединить две таблицы по общему полю;
- `EXISTS (подзапрос)` — проверить, есть ли для строки подходящая строка в другой или той же таблице;
- `CREATE TABLE … AS SELECT …` и `CREATE INDEX` — сохранить результат таблицей и ускорить поиск по полю.

## Чего SQL не делает

Графики, нестандартные функции, разбор совсем кривых форматов - остаются на Python. Рабочая схема на сегодня: **SQL считает числа, Python добавляет функции и рисует.**
