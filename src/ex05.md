# Задание 5. Как бот справляется с каждым блоком

Проверка: `python3 src/run_sql.py src/ex05.md` из корня репозитория.

### 1. Доля закрытых ботом по блокам

**Ответ:** После апреля в письменных каналах бот закрывает сам 76% обращений первой линии (1040 из 1368), половину серой зоны — 49% (588 из 1195), и только треть второй линии — 31% (39 из 125). Чем сложнее тема, тем чаще бот её передаёт: на второй линии он вообще не основной игрок.

```sql
SELECT blok, COUNT(*), AVG(bot_result = 'закрыл') AS closed_share
FROM razmetka
WHERE period = 'после' AND written = 1
GROUP BY blok;
```

### 2. Решено с первого обращения по флагу

**Ответ:** По флагу `reopened = 0` картина почти везде в пользу бота: первая линия — люди до апреля 95.1%, все после 96.0%, закрытые ботом 96.6%. Серая зона — 87.4% / 87.9% / 90.8%. Вторая линия — 92.1% у людей, 86.4% у всех после и всего 79.5% у закрытых ботом. Флаг ловит только переоткрытие того же обращения и ничего не знает о новых тикетах с той же темой.

```sql
SELECT blok, AVG(reopened = 0) AS people_before
FROM razmetka WHERE period = 'до' AND written = 1 GROUP BY blok;

SELECT blok, AVG(reopened = 0) AS all_after
FROM razmetka WHERE period = 'после' AND written = 1 GROUP BY blok;

SELECT blok, AVG(reopened = 0) AS bot_closed
FROM razmetka
WHERE period = 'после' AND written = 1 AND bot_result = 'закрыл'
GROUP BY blok;
```

### 3. Решено с первого обращения с учётом возвратов

**Ответ:** С условием `reopened = 0 AND came_back = 0` числа проседают сильнее всего именно там, где работал бот: вторая линия — было 84.2% у людей, стало 69.6% у всех после и 41.0% у закрытых ботом. В первой линии разрыв меньше (90.3% → 88.4%), в серой зоне (80.3% → 74.1%). Для вывода беру второе определение. Первое видит только клиента, который вернулся в тот же тикет, и полностью пропускает тех, кто вместо ожидания просто завёл новое обращение с той же темой — а это как раз типичное поведение после формальной отписки бота. Второе видит и тех, и других; его минус — возврат считается по совпадению темы, поэтому у тем 'NULL' и 'без темы' он засчитан быть не может и доля чуть занижена для всех групп сразу.

```sql
SELECT blok, AVG(reopened = 0 AND came_back = 0) AS people_before
FROM razmetka WHERE period = 'до' AND written = 1 GROUP BY blok;

SELECT blok, AVG(reopened = 0 AND came_back = 0) AS all_after
FROM razmetka WHERE period = 'после' AND written = 1 GROUP BY blok;

SELECT blok, AVG(reopened = 0 AND came_back = 0) AS bot_closed
FROM razmetka
WHERE period = 'после' AND written = 1 AND bot_result = 'закрыл'
GROUP BY blok;
```

### 4. Контроль: телефон

**Ответ:** На телефоне бота нет ни до, ни после, и цифры почти не двигаются: решено с первого обращения по флагу 91.0% → 89.5%, с учётом возвратов 84.5% → 82.9%. Это контрольная группа: если бы эти числа тоже заметно менялись, дело было бы не в боте, а в сезонности, составе обращений или самой выгрузке. Телефон показывает, что без бота качество держится на прежнем уровне, — значит, падение на второй линии после апреля можно относить на счёт бота.

```sql
SELECT period,
       AVG(reopened = 0) AS by_flag,
       AVG(reopened = 0 AND came_back = 0) AS with_comeback,
       COUNT(*) AS n
FROM razmetka
WHERE written = 0
GROUP BY period;
```

### 5. Сценарии

**Ответ:** Если серую зону отнести ко второй линии, бот заберёт на себя 47.5% таких обращений и решит с первого раза (с возвратами) 72.1% из них — против 80.7% у людей до апреля. Если серую оставить на первой, на вторую линию попадёт 31.2% обращений, и решёнными с первого раза окажутся только 41.0% закрытых ботом против 84.2% у людей. Второй сценарий для бота провальный, первый держится на том, что в серой зоне большинство обращений всё-таки простые.

| Сценарий | Люди до апреля | Доля закрытых ботом | Решено среди закрытых ботом |
|---|---|---|---|
| серая → вторая | 80.7% | 47.5% | 72.1% |
| серая → первая | 84.2% | 31.2% | 41.0% |

```sql
SELECT AVG(reopened = 0 AND came_back = 0) AS people_before
FROM razmetka
WHERE period = 'до' AND written = 1 AND blok IN ('вторая', 'серая');

SELECT AVG(bot_result = 'закрыл') AS bot_closed_share
FROM razmetka
WHERE period = 'после' AND written = 1 AND blok IN ('вторая', 'серая');

SELECT AVG(reopened = 0 AND came_back = 0) AS solved_among_bot_closed
FROM razmetka
WHERE period = 'после' AND written = 1 AND blok IN ('вторая', 'серая')
  AND bot_result = 'закрыл';

SELECT AVG(reopened = 0 AND came_back = 0) AS people_before
FROM razmetka
WHERE period = 'до' AND written = 1 AND blok = 'вторая';

SELECT AVG(bot_result = 'закрыл') AS bot_closed_share
FROM razmetka
WHERE period = 'после' AND written = 1 AND blok = 'вторая';

SELECT AVG(reopened = 0 AND came_back = 0) AS solved_among_bot_closed
FROM razmetka
WHERE period = 'после' AND written = 1 AND blok = 'вторая'
  AND bot_result = 'закрыл';
```

### 6. Бот → бот → человек

**Ответ:** Из 39 обращений второй линии, которые бот закрыл сам, клиент вернулся в течение недели после 15 — почти в каждом четвёртом (38%). Из этих 15 возвратов бот снова закрыл сам только 2. Остальные ушли человеку: цепочка «бот → бот» на сложных темах работает в двух случаях из пятнадцати.

```sql
SELECT COUNT(*) AS came_back_after_bot
FROM razmetka
WHERE period = 'после' AND written = 1 AND blok = 'вторая'
  AND bot_result = 'закрыл' AND came_back = 1;

SELECT COUNT(*) AS closed_again_by_bot
FROM razmetka
WHERE period = 'после' AND written = 1 AND blok = 'вторая'
  AND bot_result = 'закрыл' AND came_back = 1 AND next_bot_result = 'закрыл';
```

## Позиция

_А или Б — одной фразой, и какое число для неё решающее._

Б: бот — для первой линии, на второй нужны люди; решающее число — 41% решённых с первого обращения среди обращений второй линии, которые бот закрыл сам, против 84% у людей до апреля.
